      Breadth-First Search

      Uninformed · FIFO queue · expands by distance from the start

      A* Search

      Informed · f(n) = g(n) + h(n), h = |Δrow| + |Δcol|

      How BFS works here

      1. Put the entrance in a FIFO queue.
      2. Remove the front cell; if it is the goal, stop.
      3. Add every drivable neighbour not seen yet, remembering its parent.
      4. Follow parents back from the goal to get the route.

      Every move costs 1, so the first time BFS reaches the goal the route is the shortest. The same BFS picks the nearest free bay for each arriving car on the dashboard.

      Why A* expands fewer cells

      A* keeps a priority queue ordered by f(n) = g(n) + h(n): g is the moves so far and h estimates the moves left.

      • Admissible: Manhattan distance never overestimates when cars move in 4 directions, so A* still finds the optimal route.
      • Informed: cells that lead away from the goal get a higher f and are rarely expanded.
      • Place cones to block driveways and watch both searches re-route.

      EV Charging Scheduler

      Decision log

        Why earliest finish? The booking that ends first leaves the most time for everyone else. If an optimal schedule started with some other booking, you could swap in the earliest-finishing one without losing any car. This is the exchange argument. Sorting takes O(n log n) (merge sort) and the scan is O(n). “Chargers for all” is the largest number of bookings that overlap at once, found with a sweep line.

        Problem statement

        Shopping-mall car parks fill up quickly at weekends. Drivers waste time and fuel circling for a free bay, security guards check number plates by hand, the few EV chargers get double-booked, and management has no early warning of rush days. The result is queues at the gate and frustrated customers.

        Objectives

        • Validate number plates automatically at the gate.
        • Decide in hardware logic when the barrier may open.
        • Send each car to the nearest free bay along the shortest route.
        • Book the EV charger so the most cars get a charge.
        • Keep searchable records and forecast tomorrow's demand.

        Tech stack

        • Plain HTML, CSS and JavaScript, with no libraries or build step.
        • Every algorithm is written from scratch in js/algorithms/ (one file per subject).
        • UI code lives in js/ui/; the shared lot state is in js/lot.js.
        • Data is saved in the browser (localStorage), so the demo keeps its state between visits.
        • Responsive layout with light and dark themes.
